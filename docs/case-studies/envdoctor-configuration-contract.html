Runtime configuration / 2026

Fail before runtime.

EnvDoctor turns runtime configuration into an inspectable contract. It compares a safe environment example with a schema and reports missing, unscoped, or malformed keys without printing secret values.

Open live demo ↗View repository ↗

Problem and audience

A project can compile while its deployment configuration is incomplete. The durable job is to make required keys, shapes, ownership, and secret boundaries explicit before a service starts. EnvDoctor targets application developers, platform engineers, and reviewers of deployment changes.

Durable job

Compare a safe example against a contract before runtime and fix the missing key.

Design decision

Show the key and the rule, never the secret value. A safe failure is more useful than a leaked diagnosis.

Engineering decisions

DecisionChoiceReason
InputSafe env example and JSON schemaBounded, portable, and safe for a public demo.
ValidationRequired, URL, number, unscoped, secret-likeLocal signals remain easy to explain.
PrivacyValues are not printedConfiguration review should not create a new leak.

Architecture and media

The pipeline parses keys, normalizes the schema, applies type rules behind a masking boundary, and renders a startup decision. The repository publishes both Mermaid source and the rendered diagram.

Verified fixture behavior

The missing-key fixture returned `Startup blocked` for an absent `SECRET_KEY` and a warning for undocumented `DEBUG`. The status explicitly confirmed that values were not printed. These are fixture observations, not deployment reliability metrics.

Boundary: EnvDoctor is not a vault, secret manager, deployment adapter, or guarantee that a runtime service will start.

Next production-shaped step

Add typed schema versions, `.env` parsing, redaction tests, CI output, deployment adapters, and explicit ownership of configuration contracts.
