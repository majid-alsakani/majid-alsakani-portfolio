My Production Stack: FastAPI, Django and React

By Majid Al-Sakani (ماجد السكني) · Updated 2026-08-03

People ask me which Python framework to pick. My answer as a full stack developer who ships and maintains production systems: pick by the shape of the problem, not by benchmarks.

When I reach for Django

  • The domain is content- and admin-heavy (dashboards, roles, moderation).
  • I want the ORM, migrations, auth and admin out of the box on day one.
  • The team is small and consistency matters more than micro-optimization.

When I reach for FastAPI

  • The service is I/O bound: AI calls, external APIs, streaming responses.
  • I need typed request/response contracts and generated OpenAPI docs.
  • Latency budgets are strict and async gives real gains.

The frontend contract

React with TypeScript, a single generated API client, and no hand-written types duplicating the backend schema. Every screen declares the data it needs; nothing is fetched "just in case".

Reliability checklist I apply to every project

AreaPractice
Testingpytest for domain logic, contract tests on the API boundary
Qualityruff + type checks enforced in CI, not locally optional
OpsStructured logs, health endpoints, Docker parity between dev and prod
DataReversible migrations, backups verified by restore, not by existence
