Case studies/04 · Wasl
Local-first PWA / 2026

Knowledge that keeps going.

Wasl is an installable knowledge kit for reading and searching bounded content when connectivity is limited. It treats offline mode as a deliberate product state, with visible limits and a portable export.

Open live demo ↗View repository ↗

The problem

Many tools treat the network as a permanent dependency. In classrooms, field work, travel, and low-bandwidth settings, that assumption turns a useful reference into a blank state. Wasl explores the smallest product surface that keeps a bounded set of knowledge useful without a live request.

Primary user

Students, developers, and small field teams that need a portable reference pack more than a full collaboration platform.

Product thesis

Offline is a mode with its own contract: cache what is bounded, show connection state, and make export explicit.

What I built

CapabilityImplementationEngineering intent
Installable shellWeb App Manifest and Service WorkerMake the kit feel like a small device capability.
Knowledge packBounded local JavaScript collectionKeep the content inspectable and safe for a public demo.
SearchLocal text filtering and tagsFind the useful note without a network round trip.
PortabilityJSON export actionUsers retain a copy instead of being trapped in a session.

Architecture

Wasl moves from a knowledge pack into a cache and local store, then into search, reader, and export. Network state informs the interface but is not required for reading the bounded pack.

Evidence from the demo

In local browser testing, the pack rendered five notes. Searching `RTL` reduced the visible results to one, selected the matching note, and displayed its local-storage metadata. The Service Worker API was available in the preview context. These are interaction checks, not offline reliability benchmarks.

Decision: show “Offline · pack ready” rather than hiding the connection state. Clear limits are part of trust.

What I would build next

  • Add signed content packs and version-aware update prompts.
  • Use encrypted storage for approved sensitive content classes.
  • Design conflict-aware sync only after defining ownership and freshness rules.
  • Test install, cache invalidation, export, and recovery across target browsers and devices.

Boundary: Wasl is a local-first showcase with no accounts or sync. It does not guarantee content freshness when offline.
